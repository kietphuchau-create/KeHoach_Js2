1. Khai Báo Thư Viện Đo Lường (build.gradle)

Nạp Spring Boot Actuator và Micrometer Prometheus Registry vào tầng ứng dụng.

📄 Source_code/backend/app/build.gradle : L23-25 
// ==============================================================
// MONITORING & OBSERVABILITY DEPENDENCIES
// ==============================================================
dependencies {
    // 1. Bộ khung cung cấp các endpoint đo đạc sức khỏe & số liệu
    implementation 'org.springframework.boot:spring-boot-starter-actuator'

    // 2. Bộ chuyển đổi dữ liệu sang chuẩn chuỗi thời gian Prometheus TSDB
    implementation 'io.micrometer:micrometer-registry-prometheus'
}
📦 Vai Trò Của Spring Boot Actuator
Cung cấp các công cụ quản lý và giám sát nội tại (Production-ready features). Tự động theo dõi:
• Bộ nhớ JVM Heap & Non-Heap, các đợt dọn rác GC Pause.
• Tần suất và độ trễ của các luồng xử lý HTTP Request.
• Tình trạng hồ kết nối CSDL HikariCP Connection Pool.
🔄 Vai Trò Của Micrometer Prometheus
Đóng vai trò là "Thông dịch viên định dạng": Biên dịch toàn bộ số liệu nội bộ của Java sang định dạng chuỗi thời gian (TSDB) tiêu chuẩn công nghiệp gồm: metric_name{label=value} timestamp value để Prometheus Server có thể cào và lưu trữ được.
💡 Lưu ý kỹ thuật: Nếu thiếu thư viện micrometer-registry-prometheus, Actuator chỉ xuất được JSON thông thường chứ không thể tương thích với Prometheus.
Cấu Hình Ứng Dụng [2/4]

2. Kích Hoạt Endpoint & Nhãn Metrics (application.yml)

Mở đường dẫn xuất dữ liệu thời gian thực và gắn nhãn định danh dịch vụ MedSched.

📄 backend/app/src/main/resources/application.yml : L104-117 
# ==============================================================
# HỆ THỐNG GIÁM SÁT HẠ TẦNG & METRICS (ACTUATOR + PROMETHEUS)
# ==============================================================
management:
  endpoints:
    web:
      exposure:
        include: health, info, prometheus, metrics
  endpoint:
    prometheus:
      enabled: true
    health:
      show-details: always
  metrics:
    tags:
      application: medsched
🌐 Mở Cổng HTTP Tại /actuator/prometheus
Mặc định Spring Boot chỉ kích hoạt 2 endpoint health và info. Thuộc tính exposure.include: prometheus cho phép mở cổng HTTP để Prometheus Server từ bên ngoài có thể gửi lệnh GET đến lấy số liệu.
🏷️ Gắn Tag Định Danh Ứng Dụng (Application Tag)
Cấu hình metrics.tags.application: medsched sẽ tự động chèn nhãn app="medsched" vào từng bản ghi số liệu. Giúp Grafana lọc chính xác dữ liệu của MedSched khi triển khai chung cụm giám sát với các dịch vụ khác.
💡 Kiểm thử trực tiếp: Truy cập http://localhost:8080/actuator/prometheus (hoặc máy chủ Cloud) sẽ thấy hàng ngàn dòng chỉ số dạng text sẵn sàng cho Prometheus.

3. Cấu Hình Quyền Truy Cập (SecurityConfig.java)

Cho phép Prometheus tự động cào số liệu định kỳ mà không bị chặn bởi bộ lọc bảo mật JWT.

📄 com/medsched/security/SecurityConfig.java : L66-78 
// 1. Cấu hình các Endpoints công khai hoàn toàn (Không cần JWT Token)
.authorizeHttpRequests(auth -> auth
    .requestMatchers(
        "/",
        "/health",
        "/api/health",
        "/api/v1/health",
        "/actuator/**",  // <-- Prometheus cào metrics qua đây
        "/error",
        "/api/v1/auth/**",
        "/swagger-ui/**",
        "/swagger-ui.html"
    ).permitAll()
    // Mọi API bệnh án & đặt lịch khác đều bắt buộc xác thực JWT Token
    .anyRequest().authenticated()
)
🛡️ Tại Sao Cần .permitAll() Cho /actuator/**?
Hệ thống MedSched sử dụng kiến trúc Stateless JWT. Mọi request không kèm header Authorization: Bearer <token> đều bị Spring Security chặn lập tức với mã 401 Unauthorized.
Prometheus Server là dịch vụ chạy ngầm độc lập, không mang token người dùng, nên bắt buộc phải cấu hình permitAll().
🔒 Tính An Toàn Thông Tin (Security Audit)
Đường dẫn /actuator/prometheus chỉ xuất các chỉ số kỹ thuật phần cứng và tần suất gọi API, hoàn toàn không chứa dữ liệu cá nhân hay bệnh án. Tất cả API khám bệnh, thông tin bác sĩ và bệnh nhân vẫn được bảo vệ nghiêm ngặt 100%.
💡 Câu hỏi Thầy hay hỏi: "Mở permitAll như vậy có nguy hiểm không?" — Trả lời: "Dạ không, vì metrics chỉ chứa số đo kỹ thuật, không chứa dữ liệu y tế nhạy cảm."

4. Cấu Hình Cào Dữ Liệu Cloud & Docker Grafana

Cào máy chủ Render Production thật và ánh xạ cổng 3100 không xung đột với Next.js.

📄 Source_code/monitoring/ (prometheus.yml & docker-compose) 
# 1. File prometheus.yml: Định kỳ cào số liệu máy chủ Render thật
scrape_configs:
  - job_name: 'medsched-cloud-render'
    scheme: https
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['medsched-zu15.onrender.com:443']

# 2. File docker-compose-monitoring.yml: Cổng & Auto-Provisioning
services:
  grafana:
    ports:
      - "3100:3000"  # Tránh đụng độ cổng 3000 của Frontend Next.js
    volumes:
      - ./provisioning:/etc/grafana/provisioning
☁️ Cào Trực Tiếp Máy Chủ Cloud Render Thật
Với cấu hình scrape_interval: 5s, cứ đúng 5 giây Prometheus sẽ gửi một request HTTPS mã hóa tới máy chủ Render Production. Dữ liệu sau đó được nén và lưu trữ tối ưu trong cơ sở dữ liệu chuỗi thời gian TSDB.
🔌 Ánh Xạ Cổng 3100 & Cơ Chế Zero-Config
Cổng mặc định 3000 đã dành cho giao diện web đặt lịch Next.js. Docker ánh xạ 3100:3000 giúp chạy đồng thời cả hai trên cùng một máy.
Thư mục provisioning/ tự động nạp Data Source và Dashboard medsched-cloud-dashboard.json mà không cần cấu hình tay.
💡 Tự động hóa 1-Click: Chỉ cần chạy start-monitoring.bat là toàn bộ cụm này tự động kéo và khởi chạy trong chưa tới 15 giây.
